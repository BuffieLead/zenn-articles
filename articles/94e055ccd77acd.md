`asdf`でランタイムをインストールした後にバージョンを有効化する。プラグインとインストール済みバージョンを更新する。このような日常の操作を短く扱えるように、[asdf-extras](https://github.com/eihu0F/asdf-extras)を作りました。

この記事では、追加した操作と、それを`asdf`へつなぐ構成を紹介します。

## 欲しかった操作

`asdf-extras install nodejs 24.11.0`は、インストール後に`asdf set --home`でバージョンを有効化します。シェルを初期化すると、`asdf install -u nodejs 24.11.0`でも同じ拡張機能を使えます。`-p`/`--parent`なら親ディレクトリ側でバージョンを設定します。

`asdf-extras update`は、プラグイン全体と更新可能なインストール済みコマンドを更新します。`asdf-extras update nodejs`と対象を絞ることもできます。対象バージョンが現在と違えば、インストール、有効化、以前のバージョンの削除まで行います。

## プラグインとCLIを分ける

```text
asdf plugin add asdf-extras
  └─ bin/list-all, bin/download, bin/install
       └─ asdf-extras自身をasdfで管理

asdf-extras / asdf cmd asdf-extras
  └─ libexec/asdf-extras
       └─ lib/commands/dispatch.bash
            └─ command-install / command-update / command-init ...
```

[`bin/`](https://github.com/eihu0F/asdf-extras/tree/main/bin)はasdfプラグインの入口です。asdf-extras自身のバージョン一覧、ダウンロード、インストールをasdfへ提供します。インストール後に使うCLIは[`libexec/asdf-extras`](https://github.com/eihu0F/asdf-extras/blob/main/libexec/asdf-extras)から入り、[`dispatch.bash`](https://github.com/eihu0F/asdf-extras/blob/main/lib/commands/dispatch.bash)がサブコマンド別のスクリプトへ振り分けます。

`asdf cmd asdf-extras`はプラグインのチェックアウト内の実装を使います。一方、`asdf-extras`はasdfで選択されたインストール済みバージョンを使います。この違いが、最初の導入時と通常利用時の呼び分けにも表れています。

## シェル初期化で普段の`asdf`に重ねる

```bash
asdf plugin add asdf-extras https://github.com/eihu0F/asdf-extras.git
asdf cmd asdf-extras install asdf-extras latest
eval "$(asdf-extras init bash)"

asdf update nodejs
asdf install -u nodejs 24.11.0
```

`init`はシェル向けの初期化コードを生成します。対応するのはBash、Zsh、Fish、Elvish、Nushellです。[Bash版](https://github.com/eihu0F/asdf-extras/blob/main/lib/init/bash.sh)は`asdf`関数を定義し、`update`や拡張オプション付き`install`をasdf-extrasへ渡します。通常のコマンドは元の`asdf`へ渡します。補完も、asdfの動作に拡張分を重ねる構成です。

初期化しなくても、`asdf-extras install ...`や`asdf-extras update ...`は直接使えます。この場合、`asdf install`や`asdf update`の読み替えは行われません。

[README](https://github.com/eihu0F/asdf-extras#readme)に記載された前提バージョンは`asdf >= 0.16.0`です。導入時は最新のREADMEで対応バージョンを確認してください。

## まとめ

asdf-extrasは、asdfプラグインとして自身を導入し、CLIで追加機能を実装し、シェル初期化で普段の`asdf`コマンドにつなげています。次の記事では、この構成をGitHub Actionsでどう確認しているかを紹介します。
